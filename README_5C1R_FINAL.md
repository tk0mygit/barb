## 14件の新逆転の是正

旧入力モデルはQTE開始時に内部のheldだけを解除し、外部入力列へupを書いていなかった。
そのためQTE無効側へ再生すると、押下中の追加downがholdを再開する。
これは一本指の完全な物理入力履歴としては不十分で、旧14件を製品の無償救済バグと断定できない。
元スクリプト・CSV/JSON・失敗結果は保存し、別の[物理接触モデル](docs/phase5c1r/study/same-input-physical.mjs)を追加した。

- 元14件は**射程内13件、射程外60m stress1件**。すべてレインボートラウトで、最小長Lv1/1の6距離と最大長Lv5/10の8距離。
- 元入力での14件を再現。射程内はnative CAST/HOOK/アダプター、stressはdomainで区別した。罰・一度だけの解決・時計停止・固定arm・fps一致は維持。
- QTE開始時に実際のupを記録した固定10,368組では、0.20/0.80ともline-break→landed逆転0、打切り0。
- **これは全入力での勝敗単調性の証明ではない。** 元14件を新入力へ置き換えると、旧速度は通常slack-escape／全失敗landed、0.80は両方slack-escapeとなる。通常時計と入力の相対位相が違う反事実比較であり、別の失敗→捕獲も残る。
- 正式な固定A106は全失敗212行すべて糸切れ・全成功212行すべて捕獲、B86はfps矛盾0。4候補すべてで再確認した。

14件を消して0件と置き換えず、元入力・新入力・効果の全件対応を[final-review.json](docs/phase5c1r/final-review.json)へ保存した。
製品の罰やarmを変えてこの合成入力の結果だけを消す修正は採用しない。
