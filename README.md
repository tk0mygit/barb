# BARB

水の上に、余白を。自然の湖を船で巡る、3D Web釣りゲームの初期プロジェクトです。

Vite + Three.js + JavaScript（ES Modules）で構築しています。湖岸、森林、背景の山、
空と波のある水面を描画し、船の操縦と、一人称視点での釣りを楽しめます。
グラフィックはすべてコードから生成しており、有料素材や外部画像・フォントは使用していません。

## 開発

Node.js 24 LTS推奨（22.12以上）、npm、WebGL 2対応のブラウザが必要です。

```sh
npm ci
npm run dev
```

開発サーバーの `/barb/` を開いてください。

```sh
npm test              # 操船・カメラ・釣り状態・ジェスチャーの単体テスト
npm run build         # dist/ に本番ビルド
npm run preview       # 本番ビルドのローカル確認
npx playwright install chromium
npm run test:e2e       # ビルド後にPC・モバイル操作を確認
```

既存のChromiumを使う場合は `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` に実行ファイルのパスを指定できます。
Linuxでブラウザのシステム依存が不足する場合は `npx playwright install --with-deps chromium` を実行してください。

## 操作

- **操船**：湖の画面をマウスまたは指でドラッグ。ドラッグ距離で加速、左右の移動で旋回します。
- **停船**：マウス・指を離すと徐々に減速します。
- **キーボード**：湖の画面を選択して、↑ / Wで加速、← → / A Dで旋回できます。
- **推奨釣りポイント**：水面の薄いリングが3か所の目印です。近づくと名前を表示し、船が中心から20m以内ならアタリ発生率が1.5倍になります。範囲外でも通常どおり釣れます。
- **釣り視点**：停船中の「釣りをする」で船上の一人称視点に切り替わります。
  キャスト前はドラッグまたは矢印キーで見渡せます。
- **キャスト**：「キャスト準備」で視点を固定。湖の画面をドラッグし、左右で方向、ドラッグの長さで飛距離を調整して、離すと投げます。水面のリングと距離表示が着水予測です。岸への投射は制限します。
- **ルアー選択**：キャスト準備前に画面下部のミノー・クランクベイト・ワーム・スピナーベイトから選択。4種類とも初めから使用でき、魚種の出やすさとアタリの頻度が少し変わります。準備開始から釣果画面・失敗後の復帰までは変更できません。
- **ルアー操作**：着水後、画面の長押しで巻き取り、短いフリックでアクション。離して待つこともできます。
- **アワセ**：光と音でアタリを通知します。押している場合はいったん離し、約1秒以内に画面をタップしてください。
- **ファイト**：長押しで引き寄せ、離してテンションを下げます。高すぎるとライン切れ、低すぎる状態が続くと逃走することがあります。
- **釣果**：近づくと自動で釣り上げ、捕獲した魚種の名前・2D画像・体長・重量を表示。売却価格を確認し、「売却して続ける」または「保管して続ける」で再挑戦できます。
- **戻る・キャンセル**：キャスト前は「操船に戻る」またはEsc。準備中のEscは準備解除。キャスト後から釣果画面までは操船に戻れません。失敗後は自動でキャスト前に戻ります。

PCはマウス1つ、スマートフォンは指1本で釣りを完結できます。縦画面・横画面に対応します。
入力キャンセル・フォーカス喪失・画面非表示で長押しを解除し、キャスト準備中なら視線調整に戻ります。タブ非表示・ウィンドウ非アクティブ中はゲームを停止します。

## 構成

| ディレクトリ | 担当 |
| --- | --- |
| `src/world/` | 湖・地形・森林・山・空・水面、マップ設定 |
| `src/game/` | 船・釣りの状態遷移、確率・難易度設定、釣果データ |
| `src/input/` | Pointer Events・キーボード入力、釣りジェスチャーのマッピング |
| `src/rendering/` | 船モデル、カメラ、ルアー・ライン・水面エフェクト |
| `src/ui/` | HTML UIの状態とレスポンシブCSS |
| `tests/` | ロジック・ブラウザ操作テスト |

地形や船は生成関数を境界としているため、ゲーム状態を維持したままモデル・素材を差し替えられます。

## 現在の範囲

プロシージャルな自然景観と簡易ボートのプロトタイプです。
水面は軽量な波・反射風のシェーダー表現で、物理的な反射や高度な浮力計算は行いません。
描画負荷を抑えるため、森林はインスタンス描画、ピクセル比には上限を設定しています。
Phase 2の釣りを維持し、Phase 3A-2で12魚種の抽選・4ルアー・魚種別ファイトに拡張しています。魚の3Dモデルは使用せず、釣果のSVGはこのプロジェクト用に作成した仮画像です。効果音はWeb Audioで生成します。ブラウザの音声制限・非対応時も視覚通知で遊べます。

`src/game/fishing-config.js` で飛距離、巻き取り速度、アタリ確率、アワセ猶予、テンション難易度を調整できます。アタリは待機3秒＋平均12秒の指数分布（ルアー補正込みで平均約14〜17秒、毎回10〜20秒に収まる保証はありません）。短いフリックは一時的にヒット率を上げます。通常ファイトはテンションを調節しながら約5〜15秒が目安です。魚種と体長によって引きが変わり、大型魚はやや長くなります。抽選・ファイトの調整箇所は [釣りバランス](docs/FISHING_BALANCE.md) を参照してください。

釣果はスキーマバージョン、個体ID、魚種ID、体長cm、重量kg、捕獲日時、処理状態を持ちます。図鑑・保管はPhase 3B-1、売却・所持金・買取人はPhase 3B-2で実装済みです。Phase 3C-1Aで装備データ・購入APIを追加しています。Phase 3C-1B／1Cでロッド・リール性能を釣りへ反映しています。Phase 3C-1Dで強化UI・購入可能状態の制限・売却通知の5秒消去を追加しています。Phase 3C-2で通常実績10種類を追加しています。Phase 3C-3BでlocalStorageへの自動保存・起動時復元を接続しています。

自動テストではPCのマウス、Chromiumのタッチエミュレーション、縦横レイアウトを検証します。実機での操作感・効果音の聴感・Safariの確認と性能調整は引き続き必要です。


## Phase 3A-1・3A-2：魚種とルアー

`src/game/fish-species.js` に12魚種の通常魚データと2D画像参照を集約しています。
`getFishSpecies(id)` で取得でき、ブラックバスの従来ID・表示名・重量・抵抗値は維持しています。
12種すべてを釣り上げられ、釣果には実際に抽選された魚種IDを保存します。図鑑・保管UIはPhase 3B-1で追加しています。売却UIはPhase 3B-2で追加しています。
単位・計算式・暫定値・素材については [魚種データの説明](docs/FISH_SPECIES.md) を参照してください。

## Phase 3A-3a：推奨釣りポイント

北の沖・西の静水域・東の沖合の3地点に、中心と有効範囲の水面リングを追加しています。
判定は船のXZ座標を使い、ルアーの着水位置には依存しません。ルアー倍率と掛け合わせ、ポイント同士の重複は加算・乗算しません。
位置・半径・倍率の調整箇所と検証内容は [釣りポイント](docs/FISHING_SPOTS.md) を参照してください。

## Phase 3A-3b：水深・時間帯

岸からの半径方向の距離を使う簡易モデルで、ルアーの現在位置の水深を推定します。巻き取りにも追随します。
活動中の経過時間で昼3分・夜3分を繰り返し、非表示・フォーカス喪失中は停止します。釣りパネルに時間帯と推定水深を表示します。
水深・昼夜・ルアーの適性は魚種の抽選比率に反映し、アタリ発生率・ポイント倍率・ファイト難易度は変更しません。
抽選時の条件は釣果の追加項目 `conditions` に保持します。照明・空・霧・BGMは今後のPhase 4で接続するため、現在の見た目は昼夜で変わりません。
数値・計算式・検証内容は [水深と時間帯](docs/DEPTH_AND_TIME.md) を参照してください。


## Phase 3B-1：魚図鑑・釣果保管

右上の「≡」から魚図鑑・保管魚一覧を開けます。メニュー中はゲーム時計・釣り・操船を一時停止し、閉じると入力を解除した状態で再開します。
釣果画面では「保管して続ける」または「売却して続ける」を選択します。Escやダイアログの閉鎖でも保管され、準備状態へ戻ります。
図鑑は12魚種の固定順です。未発見魚は「？？？」とシルエット、捕獲済みの魚は詳細・累計捕獲数・自己最大体長・基準売却単価を確認できます。
保管容量は無制限で、捕獲履歴と現在の保管状態を区別します。売却後も捕獲履歴と図鑑の統計は残ります。
図鑑・保管魚・所持金は自動保存の対象です。図鑑と保管一覧は復元した捕獲履歴から再構築します。保存状態と障害時の制限は下記「自動保存と再開」を参照してください。
データ構造・操作・検証方針は [魚図鑑と釣果保管](docs/CATCH_COLLECTION.md) を参照してください。


## Phase 3B-2：魚の売却・所持金・買取人

釣果画面から即売却、保管魚一覧から個別売却・「すべて売却」ができます。一括売却では対象匹数と総額を確認し、確定またはキャンセルを選びます。
価格は既存の魚種別基準単価 × 重量kgを個体ごとに四捨五入した整数です。売却と所持金の加算は一括で確定し、同じ魚を二重に売却・再保管できません。
所持金は初期値0で画面右上とメニューに表示します。売却成功時は金額と買取人の短いセリフを5秒間表示します。連続売却は通知を置き換えて5秒を計り直し、メニューでゲームが停止していても通知は消えます。
現在の所持金と累計売却額を別々に管理しています。Phase 3C-1Aの購入APIは所持金だけを減らし、累計売却額を維持します。購入UIと状態制限はPhase 3C-1Dで追加しています。
所持金・累計売却額・売却履歴は自動保存の対象です。成功した売却と実績判定が確定してから保存します。
計算式・状態遷移・検証内容は [魚の売却と所持金](docs/FISH_SALES.md) を参照してください。


## Phase 3C-1A〜1D：装備強化UI・購入・釣り性能

ロッド・リールのLv.1〜5の価格・性能データと購入APIをゲームロジックに追加しています。
`collection.equipment` で現在レベル、`getUpgradeStatus(kind)` で次レベルと購入可能状態を取得し、`purchaseUpgrade(kind, expectedCurrentLevel)` で次レベルを購入します。費用は内部テーブルから取得し、残高減算とレベル更新を同時に確定します。古いレベルを指定した再実行は拒否します。
キャスト準備時に性能を固定し、ロッドは飛距離とテンション上昇、リールは巻き取り速度とテンション緩和へ反映します。リールLv.5は巻き取り24%・緩和16%向上。購入は次の準備から反映します。
「≡」→「装備強化」で現在／次Lvの性能・差分・価格を確認し、同じダイアログ内で購入を確定できます。操船中またはキャスト前（READY）だけ購入でき、釣り中は閲覧のみです。所持金不足・最大Lvでは購入できません。キャンセル・戻る・Esc・閉じるでは購入せず、確定時に最新状態を再確認します。購入後は画面右上とメニューの所持金、性能・購入可能状態を即時更新します。装備レベルも自動保存し、復元後の性能・次回価格は既存の装備データから取得します。
全レベルの数値・API契約・検証内容は [装備強化データと購入](docs/EQUIPMENT_UPGRADES.md) を参照してください。


## Phase 3C-2：通常実績

「≡」→「実績」で通常実績10種類の条件・進捗・解除状態・解除日時を確認できます。
捕獲・売却・強化の成功時に判定し、解除した実績名を3.5秒ずつ通知します。通知は操作を遮らず、メニュー中も自動で消えます。
捕獲履歴・図鑑・累計売却額・装備レベルを参照し、売却や装備購入で過去の実績が失われることはありません。
実績解除履歴と日時を自動保存し、復元した実績は再通知しません。報酬はありません。
条件一覧・API・通知の構成は [通常実績](docs/ACHIEVEMENTS.md) を参照してください。

## Phase 3C-3A：セーブ形式・検証・復元基盤

`saveVersion: 1` のデータ作成・JSON変換・厳格な検証・復元APIを追加しています。
捕獲履歴から図鑑と保管一覧を再構築し、所持金・累計売却額・装備・実績解除日時・船の位置と方向・ゲーム時計を復元できます。
検証成功後に新しい状態一式を構築し、未処理魚は保管へ救済します。復元した実績は再通知しません。
正式スキーマ、API、検証規則は [セーブデータと自動保存](docs/SAVE_DATA.md) を参照してください。


## Phase 3C-3B：自動保存と再開

捕獲・保管・即売却・保管魚の個別／一括売却・装備購入・実績解除をまとめて自動保存します。
最初の変更通知から250ms後にまとめて保存し、連続する自動保存の試行は最短1秒間隔に抑えます。メニューでゲームが停止していても動作します。
船の位置・方向とゲーム時計は変更があれば20秒間隔で保存し、ページの非表示・離脱時にも未保存分を同期的に保存します。
キャスト飛行・アタリ・ファイト・ランディング中の自動保存は延期し、1秒ごとに再確認して操作の判定を妨げないようにします。非表示・離脱時の保存は即時です。
画面の保存状態で、保存済み・未保存・保存失敗・利用不可・バックアップ復元・保護による停止を確認できます。
「保存失敗」「利用不可」「保存停止」の間は、今回の進行状況が保存できていません。

同じブラウザ・同じサイトで開くと、検証済みの最新記録から再開します。
捕獲履歴、保管／売却状態、所持金、累計売却額、装備、実績解除日時、船の位置・方向、ゲーム内経過時間が対象です。
復元後は速度0の操船状態で、未処理の釣果は保管へ救済します。閉じていた時間は加算せず、キャスト・ファイト・通知の途中状態は再開しません。

2スロットへ世代番号付きで交互に保存し、最新の正常スロットを直接上書きしません。
最新記録が破損していれば古い正常記録から復元し、その旨を表示します。
全記録の破損・未対応バージョン・読み込み不能時は既存記録を保護してメモリ内でプレイを続けます。
容量超過や書き込み拒否時も旧記録を保持し、再試行します。別タブによる更新を検知した場合は上書きを停止し、再読み込みで採用し直します。
保存直前にも記録を再確認しますが、複数タブで同時に編集する完全な排他制御は保証しません。1タブでプレイしてください。

保存容量はブラウザ・端末・同じサイトの利用量に依存し、2世代分の空き容量が必要です。
履歴100,000件・JSON64 Mi UTF-16コード単位という検証上限まで保存できる保証はありません。
ブラウザによるデータ消去・強制終了では保存を保証できず、プライベートブラウズの記録は終了時に失われる場合があります。
方式、停止・再開条件、上限と検証内容は [セーブデータと自動保存](docs/SAVE_DATA.md) を参照してください。
