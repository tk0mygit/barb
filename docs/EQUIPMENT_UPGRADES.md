# 装備強化データ・購入・ロッド／リール性能（Phase 3C-1C）

DOM・描画に依存しない装備データ・購入APIに加え、ロッドの飛距離・テンション上昇倍率と、リールの巻き取り速度・テンション緩和倍率を釣りへ反映しています。購入UI、釣り状態による購入制限は追加していません。

## データ

`src/game/equipment.js` の `EQUIPMENT_LEVELS` にロッド・リールを独立した配列で定義します。外側のオブジェクト、配列、各行はすべて凍結しています。バランス調整はこの定義を変更します。

| 到達Lv | 費用 | ロッド飛距離加算m | ロッドテンション係数 | リール速度倍率 | リール緩和倍率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 0 | 0 | 1.00 | 1.00 | 1.00 |
| 2 | 300 | 2 | 0.96 | 1.06 | 1.04 |
| 3 | 800 | 4 | 0.92 | 1.12 | 1.08 |
| 4 | 1800 | 6 | 0.88 | 1.18 | 1.12 |
| 5 | 3600 | 8 | 0.84 | 1.24 | 1.16 |

費用 `cost` はそのレベルへの到達費用です。累計は1装備6,500通貨、両装備13,000通貨です。性能値は常にLv.1基準で、前レベルから乗算を重ねません。
ロッドの項目は `castDistanceBonusM`・`tensionMultiplier`、リールは `reelSpeedMultiplier`・`tensionReliefMultiplier`。各行には `level`・`cost` も含みます。
`getEquipmentLevel(kind, level)` は指定レベル、`getNextEquipmentLevel(kind, currentLevel)` は次レベルの行を返します。装備IDは文字列の `rod`／`reel`、レベルは数値の整数1〜5のみです。不正なID・レベルはnullを返します。`getNextEquipmentLevel` は次レベルのないLv.5でもnullを返します。

## コレクションAPI

財布は引き続き `createCatchCollection()` が単一管理します。装備も同じコレクション内で管理し、別の財布を作りません。

| API | 戻り値・動作 |
| --- | --- |
| `collection.equipment` | 初期値 `{ rodLevel: 1, reelLevel: 1 }`。読み取り専用 |
| `collection.getUpgradeStatus(kind)` | `{ kind, currentLevel, next, canPurchase, reason }`。次レベルの費用・性能もnextから取得。不正IDはnull |
| `collection.purchaseUpgrade(kind, expectedCurrentLevel)` | 成功時 `{ kind, previousLevel, level, cost }`、失敗時null。次の1レベルだけ購入 |
| `collection.snapshot` | 既存スナップショットにequipmentを追加。JSON化可能 |

購入可能ならreasonはnull、残高不足は `insufficient-funds`、上限は `max-level`（nextもnull）です。内部の価格・残高に不正な値があれば `invalid-cost`／`invalid-balance` として購入不可にします。
照会値・購入結果・装備・財布は凍結し、取得済みの値は後の購入で変化しません。UIを接続するPhaseでは、照会は表示用に使用し、確定時は必ず購入APIで再検証します。

```js
const status = collection.getUpgradeStatus('rod');
if (status?.canPurchase) {
  const receipt = collection.purchaseUpgrade('rod', status.currentLevel);
  // receipt === nullなら未購入。最新の財布・装備・購入可能状態を再取得する。
}
```

`expectedCurrentLevel` は必須です。省略・不正値・現在レベルとの不一致を拒否します。購入後に同じ旧レベルの要求を送っても追加の購入は成立しません。次の強化には最新のレベルが必要です。ロッドの購入はリールのレベルを変えず、その逆も同じです。
購入額や到達レベルを呼び出し元から指定するAPIはありません。内部の凍結テーブルから次レベルと正規価格を取得します。

## 更新の一貫性

1. 装備IDと要求レベルを検証し、現在レベルとの一致を確認します。
2. 次レベルの有無、費用・残高が非負の安全な整数であること、残高不足でないことを確認します。
3. 減算後の安全な残高、装備、購入結果を新しい凍結オブジェクトで構築します。
4. await・コールバックを挟まず、財布と装備を同期的に置換します。

拒否時は財布・装備とも置換しません。残高が費用と等しいときは購入でき、残高0になります。
購入では `wallet.balance` だけを減らし、`wallet.lifetimeSales` を変更しません。その後の通常売却では従来どおり両方へ売却額を加算します。累計売却額10,000などの将来の実績判定は支出の影響を受けません。
捕獲履歴・保管状態・売却情報・図鑑統計には一切書き込みません。既存釣果レコードとスナップショットの `schemaVersion: 1` を維持し、equipmentを追加するだけです。

## ロッド性能の反映（Phase 3C-1B）

`createFishing().prepare()` が成功した時点で `collection.equipment.rodLevel` から `getEquipmentLevel('rod', level)` の凍結済み行を取得し、準備・飛行・ファイト・ランディング／失敗まで同じ性能を使用します。途中の購入は進行中の釣りには影響せず、次の準備開始で反映します。キャンセル後の準備も再取得します。装備情報のない従来のテスト用コレクションはLv.1扱いです。性能の参照は一時的で、別の永続装備状態は作りません。

- 最大飛距離：`castMax + castDistanceBonusM`（標準32／34／36／38／40m）。
- 要求距離：`castMin + (最大飛距離 - castMin) × clamp(ドラッグ距離 / castDragPixels, 0, 1)`。最小8m・ドラッグ基準180pxは維持します。
- 既存の0.25m刻みの経路水面判定で距離を制限し、同じ距離・方向を着水予測と実際のルアー位置に使用します。岸が近すぎる場合は従来どおりキャストを拒否します。
- 巻き取り中のテンション上昇：`tensionRise × fishResistance(魚種, 体長, 経過時間) × tensionMultiplier × dt`。Lv.1は従来同値、Lv.5は上昇量を16%抑制します。
- テンションは0〜1に制限し、魚の抵抗パターン・ライン切れ・緩み逃走判定は維持します。緩和・巻き取り速度には下記のリール倍率を適用します。大型魚ではLv.5でも連続巻き取りでライン切れが起こり得ます。
- 既存の最大1/60秒刻みの積分を維持します。30/60fpsは同一計算、144fpsとの差は抵抗曲線の数値積分誤差範囲で検証します。

## リール性能の反映（Phase 3C-1C）

成功した `prepare()` で `collection.equipment.reelLevel` から凍結済み性能行を取得します。ロッドと独立した一時参照をそのキャスト終了まで保持し、途中購入・失敗する再準備要求では更新しません。次の準備（キャンセル後を含む）で両装備の最新性能を取得します。装備情報のないコレクションはLv.1です。財布・履歴・スナップショット構造は変更していません。

- LURE回収距離：`lureSpeed × reelSpeedMultiplier × dt`。
- FIGHT回収距離：`fightDistance / (fightReelSeconds × reelResistance) × reelSpeedMultiplier × dt`。
- 巻き取り停止時のテンション減少量：`tensionRelief × tensionReliefMultiplier × dt`。

`fightDistance` はアワセ時のランディング地点までの残距離、`reelResistance` は従来どおり魚種・体長・時間の抵抗を0.8〜1.25へ制限した値です。巻き取り停止時は距離を減らしません。距離下限4.5m、テンション0〜1、ライン切れ・緩み逃走、ランディング演出後の1回だけの釣果登録を維持します。ヒット抽選式・キャスト飛距離・ルアーアクションは変更していません。速い回収で実際のルアー位置が変わると、その地点の水深を使う既存の抽選は引き続き働きます。

| Lv | LURE速度 m/s | 緩和速度 /秒 |
| --- | ---: | ---: |
| 1 | 0.650 | 0.4200 |
| 2 | 0.689 | 0.4368 |
| 3 | 0.728 | 0.4536 |
| 4 | 0.767 | 0.4704 |
| 5 | 0.806 | 0.4872 |

`tests/reel-performance.test.js` で全5レベル、12魚種×最小／中間／最大体長、ロッドLv.1／5、30/60/144fpsの距離・テンション計算を検証します。準備・飛行・LURE・BITE・FIGHT中の単独／両装備購入、性能固定、次回反映、旧コレクション互換、3ポイント・4ルアーのヒット時間と抽選、回収終了も確認します。

長押し220ms・100msごとの判断（35%未満で押し始め、65%超で離す）による全12種×3体長×3fpsの108通りを各装備組合せで検証したファイト時間：

| ロッドLv | リールLv | 最短〜最長 |
| --- | --- | --- |
| 1 | 1 | 6.63〜16.85秒 |
| 1 | 5 | 5.53〜12.68秒 |
| 5 | 1 | 6.63〜15.75秒 |
| 5 | 5 | 5.52〜11.57秒 |

難易度上の注意：両装備Lv.5では最小・中間体長のブルーギルが緩めず連続巻き取りだけで捕獲できます（12種×3体長の2/36ケース、30/60/144fps共通）。初期装備では0/36ケースで、全ケースがライン切れでした。指定倍率に伴う難易度低下として記録し、倍率は調整していません。

最大強化でも大型魚は緩める操作が必要で、最大体長のアリゲーターガーは連続巻き取りでライン切れ、放置で緩み逃走を再現できます。全組合せで12種を捕獲でき、即時ランディングは起きませんでした。初期装備の大型魚には従来から15秒超のケースがあります。指定倍率は変更していません。これは再現可能な操作モデルでの検証であり、実機の操作感評価ではありません。
