# 魚の売却・所持金・買取人（Phase 3B-2）

## 操作

- 釣果画面で価格を確認し、「売却して続ける」または「保管して続ける」を選びます。Escや通常のダイアログ閉鎖は保管です。売却・保管のどちらも成功後はキャスト前へ戻ります。
- 「≡」→「保管魚」で各個体の価格を確認し、「この魚を売却」で個別売却できます。
- 「すべて売却」は現在の保管中の通常魚を対象とし、匹数と総額を同じメニューダイアログ内で確認します。「売却を確定」で一括処理、「キャンセル」・戻る・Esc・閉じるでは変更しません。0匹なら実行不可です。
- 売却後は一覧と所持金を即座に更新し、金額と買取人の短いセリフを表示します。図鑑の捕獲数・最大体長は維持します。

メニューの間は既存どおり操船・釣り・カメラ・ゲーム時計を停止します。画面を閉じる際に入力を解除して再開します。
**所持金・累計売却額・売却履歴もセッション中のみです。再読み込みで失われます。** 保存・復元処理はありません。

## 価格と金額

`src/game/fish-sales.js` の `calculateSalePrice(record)` が唯一の価格計算です。

```text
個体の売却価格 = 四捨五入(fish-species.jsのbasePricePerKg × weightKg)
一括売却総額 = 個体ごとに四捨五入した価格の合計
```

全12魚種の既存単価をそのまま使用します。たとえば単価90・重量1.15kgなら104通貨、同じ個体2匹なら208通貨です。
JavaScriptの浮動小数点誤差で `90 * 1.15` が103.499999…になるため、重量の十進表現をBigIntで計算し、半端を切り上げて整数のNumberへ戻します。BigIntは計算内部だけで使用し、スナップショットに含めません。
不明魚種、不正な重量、安全整数を超える価格を拒否します。価格・所持金・累計売却額は0以上の安全な整数とし、`addMoney` で加算結果も検査します。

## 状態と一括処理

捕獲履歴の基準データは引き続き `catch-collection.js` です。許可する遷移は `unassigned → stored`、`unassigned → sold`、`stored → sold` です。
`sellUnassigned(id)` は釣果画面専用、`sellStored(ids)` は保管魚だけを対象とします。同じIDの重複指定、未知ID、対象外状態が1件でもあればnullを返し、何も変更しません。
売却済み個体の再売却・再保管は不可です。各レコードは凍結した新しいオブジェクトで置換し、個体ID・魚種・サイズ・捕獲日時・環境条件を保持します。売却金額 `salePrice` とISO形式の売却日時 `soldAt` を追加します。

処理順序は「全件の状態・価格と総額を検証 → 更新後の所持金・累計額・日時を検証 → 新しいレコード・履歴・領収情報を構築 → 履歴と財布を同期的に置換」です。
途中にawaitやUI処理はなく、金額上限や日時の検証に失敗した場合も一部だけ売却することはありません。
成功時の領収情報は `{ ids, count, total, soldAt }`。UIは成功時だけ所持金表示とセリフを更新します。

一括確認用の `quoteStored()` は凍結した `{ ids, count, total }` を返します。確認時のID一覧を確定処理へ渡し、再度全個体が保管中か検証します。表示後に追加された別個体は含めず、対象が売却済みなどに変わっていれば全件拒否します。
確認を取り消すと保留情報を破棄します。連打や古いボタンのイベントでも同じ売却を二度成立させません。

`closeResult()` は従来どおり保管とbooleanの戻り値を維持し、`sellResult()` を別の経路として追加しています。どちらも釣果状態でのみ確定可能です。即売却で準備状態へ戻った後にdialogのcloseが届いても保管されません。

## 財布・将来の保存

`collection.wallet` は `{ balance: 0, lifetimeSales: 0 }` から開始します。両方を売却額だけ加算し、履歴と同時に確定します。画面はbalanceを表示し、将来の累計売却額10,000の実績はlifetimeSalesを参照できます。
支出機能は未実装ですが、将来の装備強化はbalanceだけを減らし、lifetimeSalesを維持する設計です。
`collection.snapshot` は既存の `schemaVersion: 1`、`catches`、`storedIds`、`encyclopedia` に `wallet` を追加したJSON化可能な読み取り専用データです。売却済みの個体もcatchesに残り、storedIdsからは除外されます。既存の釣果スキーマを変更せず追加項目で拡張しています。
スナップショットは取得時点の値なので、売却後は再取得してください。保存・復元APIや独自の暫定セーブは追加していません。

## 買取人と表示

`src/game/buyer-lines.js` に通常の買取人の短い日本語セリフを4種類用意し、成功時に1つ選びます。既定の乱数源は `crypto.getRandomValues` で、魚種抽選やファイトが使用する `Math.random` と分離しています。テストでは乱数関数を注入できます。
`src/ui/sales-hud.js` が所持金・領収情報・セリフを表示し、UIで価格式を再実装しません。買取人のモデル・画像・音声はありません。

## 検証と対象外

単体テストで全12魚種・重量・端数処理、初期財布、即売却・保管後売却、一括総額、二重処理・不正IDの拒否、金額上限時の全件拒否、図鑑の維持、凍結レコード・環境条件・JSON化、実際の捕獲からの即売却、セリフ乱数の独立性を検証します。
ブラウザではPC・タッチで実際に4匹を捕獲し、3経路の売却、連打、保管との排他性、Esc・通常close、空一覧、確認キャンセル、縦横表示、所持金・セリフ・図鑑統計、メニュー中の時計停止と再開、再読み込み後の初期化を確認します。既存の全12魚種捕獲・環境抽選・操船テストも維持しています。
既存のアワセE2EはソフトウェアWebGL環境で検出から入力まで1秒以上かかるため、アタリ待ちをテスト時計で進め、入力送信中は時計を停止します。実際のポインター入力と本番の状態遷移を使用し、ゲームの受付時間は変更していません。アワセ後は時計を再開し、従来のファイト操作を確認します。
実行コマンドは `npm ci`、`npm test`、`npm run build`、`npm run test:e2e`。最終結果はPRに記載します。

装備強化・支出、実績、永続保存・復元、朝夜の描画・霧・BGM、新しい魚種は対象外です。GitHub Pages設定・釣りバランスを変更せず、非公開設定も追加していません。
スマートフォン実機・Safariは未確認です。既存のThree.jsチャンクサイズ警告は継続しています。
