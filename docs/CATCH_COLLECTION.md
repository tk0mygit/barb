# 魚図鑑・釣果保管（Phase 3B-1〜3B-2）

## 操作

右上の「≡」から「魚図鑑」「保管魚」を開きます。閉じるボタンまたはEscでゲームへ戻ります。
図鑑は仕様書の12魚種を固定順で表示します。未発見の枠は共通の魚シルエットと「？？？」だけを表示し、名前・説明・価格・魚種固有画像をDOMへ渡しません。
捕獲済みの枠を選ぶと、画像・魚種名・累計捕獲数・自己最大体長・基準売却単価（通貨/kg）・説明を確認できます。
魚種情報は既存の `fish-species.js` を参照し、別の魚種カタログを作りません。

釣果画面の「保管して続ける」で保管を確定し、キャスト前へ戻ります。Esc、プラットフォームのダイアログ閉鎖でも同じ保管処理を呼びます。
Phase 3B-2では「売却して続ける」も選べます。売却成功後のcloseイベントは保管を追加実行しません。廃棄操作はありません。
保管一覧は新しい順で、画像・魚種名・体長・重量・捕獲日時（閲覧端末の現地時間）・個体IDを表示します。同種・同サイズでも個体IDで区別できます。
容量制限はなく、一覧はスクロールでき、画像は遅延読み込みします。保管中の魚が0匹なら空状態を表示します。各個体の価格と売却ボタン、一括売却の確認画面を追加しています。

所持金を含む正規データはPhase 3C-3Bの自動保存対象です。保存に成功した記録から復元し、図鑑・保管一覧を再構築します。保存状態と制限は[セーブデータと自動保存](SAVE_DATA.md)を参照してください。
メニューと釣果画面にもこの注意を表示します。localStorage、独自の暫定セーブ、データ復元は追加していません。

## データ管理

`src/game/catch-collection.js` はDOM・描画に依存しません。`createFishing()` が標準でコレクションを所有し、必要なら生成時に `collection` を渡せます。

| API | 意味 |
| --- | --- |
| `register(record)` | ランディング完了時に捕獲履歴と図鑑を更新。同じ個体IDの再登録は既存レコードを返すだけ |
| `store(id)` | 未処理の個体を保管。既に保管済みなら同じレコードを返し、未知のID・売却済み個体はnull |
| `sellUnassigned(id)` | 未処理個体を即売却。成功時は領収情報、失敗時はnull |
| `sellStored(ids)` | 指定した保管中の個体を一括売却。1件でも不正なら全件未処理 |
| `quoteStored()` | 現在の保管個体ID・匹数・総額。対象なし／価格不正はnull |
| `wallet` | 読み取り専用のbalance（所持金）・lifetimeSales（累計売却額） |
| `catches` | 未処理個体も含む全捕獲履歴。現在のdispositionを含む読み取り専用配列 |
| `stored` | dispositionがstoredの個体のみ。売却済み個体を除外 |
| `encyclopedia` | 固定順のspeciesId・count・maxLengthCm。未発見の最大値はnull |
| `equipment` | ロッド・リールの現在レベル（Phase 3C-1A、読み取り専用） |
| `getUpgradeStatus(kind)` / `purchaseUpgrade(kind, expectedCurrentLevel)` | [装備強化](EQUIPMENT_UPGRADES.md)の照会・購入API |
| `snapshot` | schemaVersion・catches・storedIds・encyclopedia・wallet・equipmentをまとめたJSON化可能な読み取り用スナップショット |

釣果の `schemaVersion: 1`、個体ID・魚種ID・体長cm・重量kg・捕獲日時・環境条件 `conditions` は維持します。
`state.catches` は同じ捕獲履歴を返すgetter、`state.catch` は釣果画面で扱う現在の個体です。
捕獲時のdispositionは `unassigned`、保管後は `stored`、売却後は `sold`。売却時には `salePrice` と `soldAt` を追加します。凍結済みレコードを直接変更せず、新しいレコードに置き換えます。
既に取得した過去のレコードやスナップショットは変化しないため、最新状態は再取得してください。
`closeResult()` は保管が成功した場合のみ準備状態へ進みます。繰り返し呼んでも二重保管・二重登録を行いません。

`sellResult()` は即売却が成功した場合のみ準備状態へ進み、領収情報を返します。`closeResult()` の既存の保管動作・booleanの戻り値は維持しています。

図鑑統計は `register` による初回個体登録時だけ更新し、保管・売却では変更しません。未保管でも発見済みです。
履歴・保管状態と統計を分離しているため、売却済みに変更しても図鑑の発見・累計・最大値を維持できます。
価格計算と売却の検証・一括更新の詳細は [魚の売却と所持金](FISH_SALES.md) を参照してください。削除APIはありません。

保存では `snapshot` の派生一覧をそのまま保存せず、正式スキーマの捕獲履歴・所持金・累計売却額・装備レベルを使い、保管・図鑑は再構築します。
履歴が基準データで、storedIdsと図鑑統計は履歴から照合・再構築可能な派生値です。復元APIや移行処理は後続Phaseで設計します。

## メニューとゲーム進行

`src/ui/collection-menu.js` は単一のネイティブdialog内でメニュー・図鑑・詳細・保管一覧・一括売却確認を切り替えます。
複数のモーダルを重ねず、釣果表示中はメニューボタンを無効化し、開く処理でも状態を再確認します。
メニュー中はネイティブdialogの背景操作遮断に加え、入力モジュールの `setEnabled(false)` でポインター・キー・長押しを解除します。
操船、カメラ、キャスト、アタリ猶予、ファイト、共有ゲーム時計の更新を停止します。準備中のキャストは解除されます。
閉じる際にも入力とフレーム基準時刻をリセットし、休止中の時間の追いつき加算や押しっぱなしを防ぎます。
フォーカス喪失・非表示時の既存ルールも維持します。釣果画面の時計は従来どおり進み、コレクションメニューでは停止します。

## 検証・対象外

単体テストでは固定順、捕獲時の発見、同魚種の累計・最大値、保管との独立性、重複ID、繰り返し保管、凍結レコード・環境条件の維持、1,000個体の保管、実際のランディングと再挑戦を検証します。
既存の捕獲テストでは、保管後にレコードを置き換える仕様に合わせて比較を更新し、魚種・サイズ・重量などの期待値は維持します。
ブラウザではPC・タッチ、未発見情報の非表示、縦横画面、時計・アタリ・ファイトの停止、長押し解除、釣果との競合防止、図鑑詳細・保管一覧、全12魚種の固定順、スクロール、再読み込み時の復元を検証します。
実行コマンドと最終結果はPRに記載します。

装備強化、実績、自動セーブ・復元、朝夜の描画・霧・BGMは対象外です。
既存の湖・操船・カメラ・4ルアー・12魚種・環境抽選・ポイント倍率・GitHub Pages設定を維持し、新しい魚種や非公開設定は追加していません。
スマートフォン実機とSafariの操作感・性能は未確認です。Three.jsの既存チャンクサイズ警告は継続しています。
