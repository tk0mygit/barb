# 水深・時間帯による抽選補正（Phase 3A-3b）

通常12魚種の一般的な生態を参考にした**ゲーム用の暫定値**です。実際の生息域・湖底形状を再現するものではありません。
ポイント配置、アタリ発生率、ファイト係数、照明・空・水面・霧・音は変更していません。

## 簡易水深モデル

`src/world/depth.js` の `estimateWaterDepth({x, z})` が水深を返します。
`DEPTH_CONFIG` で最大水深・沖合距離・曲線の指数・深度区分の境界を調整できます。

```text
岸からの余白m = max(0, shoreRadius(atan2(z, x)) - hypot(x, z))
推定水深m = maxDepthM × min(1, 岸からの余白m / offshoreDistanceM) ^ exponent
```

| 設定 | 初期値 |
| --- | --- |
| maxDepthM | 12m |
| offshoreDistanceM | 90m |
| exponent | 1.2 |
| shallowLimitM | 3m（未満が浅瀬） |
| deepStartM | 8m（以上が深場、3〜8m未満が中深度） |

これは原点から伸びる半径方向の余白で、実際の最短湖岸距離ではありません。岸付近ほど浅く、沖合ほど深くなり、最大12mで飽和します。
湖外・欠落・非数値・非有限な座標は水深0として扱い、不正な抽選値を作りません。非常に大きな有限座標も湖外として0になります。
魚種抽選では、巻き取り後の `origin + heading方向 × 現在の残距離` をルアーの水面位置として使用します。
船の位置や最初の着水地点への固定はしません。描画と抽選で同じ `getLurePosition` を使用します。
今後は `estimateWaterDepth` または釣り処理に渡す `getEnvironment(position)` を差し替えることで、水底データを接続できます。3D水底は追加していません。

## 共有ゲーム時計

`src/game/game-clock.js` の `createGameClock()` をアプリ全体で1つ生成します。
`step(dt, paused)` は秒単位の時間差分を加算し、読み取り専用の `state` から以下を取得できます。

| 項目 | 内容 |
| --- | --- |
| elapsedSeconds | 活動中の累積経過秒 |
| cycleSeconds | 6分周期内の経過秒（0以上360未満） |
| cycleProgress | 周期内進行度（0以上1未満） |
| timeOfDay | day / night |
| phaseProgress | 昼または夜の区間内進行度（0以上1未満） |

初期値は昼、0〜180秒未満が昼、180〜360秒未満が夜で、360秒から昼に戻ります。
`GAME_CLOCK_CONFIG` の `daySeconds` / `nightSeconds`（各180）で調整できます。
加算には誤差補償を使い、境界での1ナノ秒未満の丸め誤差を吸収します。30・60・144fpsで同じ切り替えになります。
`Date.now()` は使いません。既存の釣果の捕獲日時は従来どおり壁時計の日時ですが、昼夜計算には使いません。

アプリは `requestAnimationFrame` の単調増加するタイムスタンプの差を渡します。
画面非表示・ウィンドウ非アクティブ中は時計とゲーム更新を停止し、復帰時に基準時刻をリセットするため、休止中の時間を後から加算しません。
操船・釣り・釣果画面では時間が進みます。目に見えている間の低フレームレートでも、時計にはフレーム間の経過秒をすべて渡します。
移動・釣りシミュレーションには従来の250ms上限を維持します。時計の1回の大きな更新でも複数周期を正しく処理します。
将来の一時停止メニューでは `step(dt, true)` または更新を呼ばない方式を使えます。
Phase 4の照明・空・霧・BGMにはこの同じ時計の `state` を渡してください。現時点では描画・音には接続していません。

## 適性データと計算

`src/game/encounter-affinities.js` に魚種別・ルアー別の適性を集約しています。

| 魚種ID | 浅瀬 | 中深度 | 深場 | 昼 | 夜 |
| --- | --- | --- | --- | --- | --- |
| black-bass | 1.20 | 1.10 | 0.85 | 1.10 | 0.95 |
| smallmouth-bass | 0.95 | 1.20 | 1.10 | 1.10 | 0.95 |
| bluegill | 1.30 | 1.00 | 0.80 | 1.20 | 0.80 |
| rainbow-trout | 0.90 | 1.15 | 1.25 | 1.15 | 0.95 |
| brown-trout | 0.95 | 1.10 | 1.20 | 0.95 | 1.20 |
| iwana | 1.05 | 1.20 | 1.10 | 1.10 | 1.00 |
| northern-pike | 1.20 | 1.15 | 0.90 | 1.15 | 0.95 |
| european-perch | 1.15 | 1.20 | 0.90 | 1.20 | 0.85 |

浅場のブルーギル・アロワナ、冷水を好むトラウト類、暗い時間に活動しやすいウォールアイ・ナマズなどの特徴を緩やかな差にしています。
地域・季節・種類による生態の違いを網羅する値ではありません。

| ルアー | 浅瀬 | 中深度 | 深場 |
| --- | --- | --- | --- |
| ミノー | 1.15 | 1.00 | 0.85 |
| クランクベイト | 0.90 | 1.15 | 1.20 |
| ワーム | 1.05 | 1.10 | 1.15 |
| スピナーベイト | 1.20 | 1.10 | 0.80 |

```text
B = 魚種の基本出現ウェイト
A = ルアーの魚種適性（既存値）
D = 現在水深に対する魚種適性
L = 現在水深に対するルアー適性
T = 昼夜の魚種適性
有効ウェイト = B × A × D^L × T
             = B × A × D × D^(L - 1) × T
抽選確率 = 有効ウェイト / 全魚種の有効ウェイト合計
```

全魚種に同じ `L` を単純乗算すると、正規化で消えて比率が変わりません。
ここでは `L` を水深による有利不利の強さとして使います。高適性のルアーは、その水深に適した魚をやや選びやすくし、低適性では水深による差を緩和します。
例：魚種の水深適性1.3に対して、L=1.2なら約1.370、L=0.8なら約1.234です。これはヒット率の上げ下げを表す値ではありません。
全値を正に保ち、24条件（4ルアー×3水深×昼夜）で各魚種の確率は約0.94〜29.86%です。全条件で全12種が抽選対象です。

`getSpeciesProbabilities(lureId, conditions)` と `sampleFishSpecies(lureId, random, conditions)` の条件は任意です。
`conditions` は `depthM`・`timeOfDay` を使用し、`cycleProgress` は記録用です。省略した要素や不正な要素はその補正を1として扱うので、旧呼び出しの確率は維持します。
魚種やルアーの環境適性が未登録なら1を使用します。乱数の呼び出し回数・固定順は維持し、同一条件・同一乱数で結果を再現できます。

## 抽選時点・釣果との互換性

アタリ発生時に現在位置の環境を取得して魚種・体長を決め、`state.encounter.conditions` に凍結したスナップショットを保持します。
その後に昼夜が変わったり魚を引き寄せたりしても再抽選せず、釣果へ同じ条件を渡します。
`conditions` は水深m、深度区分、昼夜、周期進行度、ルアーID、ルアーの水面XZ位置です。
釣果の既存フィールドと `schemaVersion: 1` は維持し、任意の追加フィールドとして扱います。旧レコードにこの項目がなくても魚種ID・体長・重量の参照方法は変わりません。
環境取得を渡さない `createFishing` の従来の単体利用も従来の確率・釣果形式を維持します。

ポイント判定は引き続き**船のXZ位置**、水深判定は**ルアーのXZ位置**です。
アタリ発生率は従来のルアー倍率×ポイント倍率×フリック倍率だけで、環境補正を入れません。
通常の平均待ち時間約14〜17秒と、ポイント内の1.5倍補正を維持します。ファイトも既存の魚種・体長の抵抗のみを使います。
