# 昼夜の環境描画（Phase 4A）

`createGameClock()` の共有時計だけを使い、昼0〜180秒未満・夜180〜360秒未満の判定と6分周期を維持します。
描画の薄明は魚種抽選の時間帯判定を変えません。壁時計や別の昼夜タイマーは使用しません。

## 補間と描画

`src/world/day-night.js` はThree.js・DOMに依存しない決定的な計算です。
`cycleSeconds` から太陽の周回方向、`timeOfDay` と `phaseProgress` から正弦波の高度を求めます。
高度をsmoothstepで補間し、昼の青緑系から薄明の穏やかな暖色、夜の深い青へ遷移します。
色はlinear RGBで補間します。180秒・360秒の両側で値と変化が連続し、直前フレームへの依存がありません。
長いフレームで複数周期を飛び越えても、時計の現在値に直接一致します。
呼び出し側が計算結果の配列を再利用できます。

- 既存の`Sky`の昼間の散乱・太陽円盤を使い、夜は同じシェーダー内で軽量な青のグラデーションへ補間します。
- 既存の`HemisphereLight`は強度0.65〜2.4。夜も船・岸・木の輪郭を判別できる環境光を残します。
- 既存の太陽`DirectionalLight`は強度0〜3.2。影は従来の1024×1024マップ1枚を維持します。
- 月は低分割の球1個で、水平線付近から滑らかに現れます。月光の`DirectionalLight`は強度0〜0.55で影を生成しません。
- 空気遠近の密度は従来の0.0018固定。色だけを時間帯に合わせます。確率による夜霧や天候の追加はありません。
- 水面の深部色・反射色・太陽／月の方向とハイライト量をuniformへ渡します。水面と遠景は同じ霧の色・指数式を使います。
  波・航跡・水面アニメーションは従来の式を保ち、夜は細部の明るさを抑えます。

空・月・ライトは船の周囲へ配置し、光源方向と水面のハイライト方向を一致させます。
船・釣り対象のリング／ライン・HUDは既存の描画と操作を維持します。
反射用の追加レンダーターゲット、外部素材、ポストプロセスは追加しません。
昼夜更新時にマテリアル・ジオメトリ・GPUリソースを生成しません。
月の追加は最大1ドローコールで、影の追加パスはありません。

## 更新・復元の順序

1. 既存の2スロット検証・復元で時計を含むドメイン一式を採用します。
2. モデル・カメラ・HUDを保存状態へ接続します。
3. `lake.update(0, boat, gameClock.state)`で環境を設定します。
4. `resize()`の同期的な初回描画を行います。
5. 初期化成功後に自動保存を開始します。

アニメーションでは時計を更新した後、そのスナップショットを`lake.update(elapsed, boat, clockState)`へ渡してから描画します。
第1引数は既存の波・航跡用のアニメーション時間で、昼夜計算には使いません。
メニュー・非表示・フォーカス喪失中は時計と描画更新を止め、復帰時にフレーム基準時刻をリセットします。
停止中の回転・リサイズによる再描画でも設定済みの環境を使います。
セーブv1・2スロット・復元処理は変更せず、環境パラメータ自体は保存しません。

## 検証と制限

`tests/day-night.test.js`は境界・周期の連続性、全周期の有限値／強度下限、光源方向、
30/60/144fps、停止、大きな時間差分、復元直後の設定、GPUリソース参照の再利用を検証します。
`tests/browser/day-night.spec.js`は本番ビルドの実際の最初の`render()`をThree.jsの既存devtoolsイベントで観測します。
時計・保存記録・ブラウザ入力の制御はテスト内だけで行い、プレイヤー向けのデバッグAPIや操作は追加しません。

E2Eは昼・夕暮れ・夜・朝、夜のFPS釣りの画像と`renderer.info`のドローコール／三角形数／GPUリソース数を保存します。
GitHub Actionsの`browser-test-results`成果物から確認できます。生成画像はリポジトリへコミットしません。
ソフトウェアWebGLの計測は実機のFPS保証ではありません。スマートフォン実機・Safari／WebKitの検証は未実施です。
月はテクスチャなしの簡易表現で、水面反射は既存のFresnel＋ハイライトによる近似です。
夜霧の抽選・音・新しい天候は後続の対象です。
